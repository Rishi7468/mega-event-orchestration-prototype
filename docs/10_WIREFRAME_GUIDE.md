# 10 — Wireframe Guide

## Purpose

The wireframes define information architecture, hierarchy, layout, and interaction intent.

They are not pixel-perfect design specifications.

Claude should use them together with the written documents.

## Wireframe folder

Expected folder:

```text
wireframes/
```

Expected files:

```text
Wireframe 1 — Visitor Home.png
Wireframe 2 — Accommodation Intelligence.png
Wireframe 3 — Recommended Stay.png

```

If the exact filenames differ slightly, match them semantically rather than creating duplicate files.

## Wireframe 1 — Visitor Home

Reference for:

- mobile navigation
- event context
- Plan My Visit CTA
- compact live status
- visitor-first hierarchy

Implementation should preserve the mobile-first nature.

## Wireframe 2 — Accommodation Intelligence

Reference for:

- map + recommendation cards
- zone-level accommodation intelligence
- comparison
- crowd/capacity context

The key concept is that the visitor is choosing a **zone/resource combination**, not simply browsing hotels.

## Wireframe 3 — Recommended Stay

Reference for:

- recommendation explanation
- trade-offs
- clear primary CTA

The "Why we recommend this" area is essential.

## Wireframe 4 — Journey Planner

Reference for:

- vertical journey
- transport stages
- arrival time
- route recommendation

The journey should feel generated by the intelligence engine.

## Wireframe 5 — Live Journey

Reference for:

- current step
- next action
- live conditions
- contextual alert

Avoid turning this into a dashboard.

## Wireframe 6 — Dynamic Re-optimization

This is one of the most important wireframes.

It represents:

```text
Existing plan
    ↓
New event signal
    ↓
System predicts problem
    ↓
Alternative plan
    ↓
Visitor chooses
```

The UI should make the change understandable within seconds.

## Wireframe 7 — Operator Command Center

Reference for:

- desktop layout
- map
- KPI strip
- intelligence panel
- camera feeds

This should feel operational.

## Wireframe 8 — Demand & Capacity Intelligence

Reference for:

- destination-wide capacity
- zone comparison
- pressure distribution
- operator intervention

This screen proves that the product is not only a visitor navigation app.

## Wireframe 9 — Live Event Card

Reference for:

- highly contextual mobile alert
- current location
- gate comparison
- one clear action

This is a key real-world state.

## How Claude should use the wireframes

Use the wireframes to answer:

- Where does this information appear?
- What is the hierarchy?
- What is the primary action?
- What information is grouped together?
- What is visible without scrolling?

Use the Markdown documents to answer:

- Why does the screen exist?
- What should the system calculate?
- What should happen after the action?
- What data should be displayed?

## Do not blindly copy

The wireframes are deliberately low-fidelity.

Claude should improve:

- spacing
- typography
- responsive behavior
- accessibility
- component quality
- visual hierarchy

without changing the product concept.
